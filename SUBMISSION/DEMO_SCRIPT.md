# Three-minute demo script

**Target length:** 2:50–3:00. Keep the screen recording continuous where practical. The script assumes the deployed demo is available; if a live provider is not verified, say so and use the clearly labelled mock/synthetic path rather than implying a live call.

## 0:00–0:20 — The problem and promise

**Screen:** Reel2Play landing page, then `/try`.

**Say:**
"Small businesses already make product Reels, but turning each Reel into an interactive ad takes design, development, and testing. Reel2Play turns a shop-owned product video into a short playable mini-game ad, with a shareable game page and campaign assets."

## 0:20–0:45 — Input and rights

**Screen:** Choose a labelled synthetic sample on `/try`, or a real shop video only if permission is documented. Show the rights confirmation and the shop's product/price/offer brief.

**Say:**
"We start with a video the shop owns or has permission to use. The owner confirms rights, and the original audio is removed. The shop's own price and offer take priority over guesses from the video."

## 0:45–1:20 — Director and product preparation

**Screen:** Start the sample. Show live progress and the director's findings/why panel. If configured and verified, show the provider/model label or a safe provider log with secrets removed.

**Say:**
"The director analyses the product, brand cues, and offer, then proposes a structured game configuration. Product cut-out is a separate step. The model proposes; our application code validates the configuration and builds from fixed game templates."

**Important:** Only name Muse Spark Open, SAM 3.1, or Muse Glimmer as having executed in this recording if you have evidence from this run. Otherwise say: "The architecture has provider slots for Meta's open-weight models; this recording uses [verified provider or mock mode]."

## 1:20–1:55 — Play and test

**Screen:** Open the resulting game, play it, show the end card. Then show the tester report/quality gates and, if available, one actual fix-loop iteration.

**Say:**
"The builder compiles the structured configuration into a game. The tester checks playability and quality gates. A failed check can return for a bounded fix attempt; if it still cannot pass, the workflow reports that a person needs to review it rather than presenting a failed game as ready."

## 1:55–2:25 — Publishable outputs

**Screen:** Show the ad/share page and available assets: game link, gameplay Reel, captions, QR poster, embed snippet, Meta playable export if actually generated.

**Say:**
"A successful build can produce a hosted game link and campaign assets. The hosted page is the practical route for ordinary shops; the Meta playable export is intended for the App Installs format. The exact outputs shown here are [name only the outputs visibly generated in this run]."

## 2:25–2:45 — Safety and transparency

**Screen:** Show rights/safety explanation, audit/why panel, and the synthetic label if using synthetic media.

**Say:**
"Safety is part of the workflow: rights confirmation, audio removal, blocked product categories, coupon-only rewards, prompt-injection handling, and isolated play-testing are designed into the pipeline. This sample is labelled synthetic; we do not present it as a real shop result."

## 2:45–3:00 — Close

**Screen:** Return to the project name and `Built with Muse Spark Open` attribution.

**Say:**
"Reel2Play helps a small shop turn an existing product video into something customers can play, share, and act on. Built with Muse Spark Open."

---

## Recording substitutions

- **No live keys:** use the mock provider and state that it is a mock/synthetic demonstration. Do not imply live model execution.
- **No real shop consent:** use only the bundled synthetic sample. Keep the synthetic label visible.
- **No populated gallery:** show `/try` and explain that the 30-real-video gallery is still pending; do not fabricate entries.
- **No Meta playable export in the run:** omit that output from the spoken claim; do not show an old file as if generated in this run.
