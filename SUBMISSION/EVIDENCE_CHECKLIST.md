# Evidence checklist — support every claim

Save evidence locally in a private working folder. Only publish redacted, permission-cleared evidence. Never include secrets, private consent forms, personal phone numbers, or raw customer media without approval.

| Claim area | Evidence to capture | Claim boundary |
|---|---|---|
| Muse Spark Open | Redacted provider configuration and request/response record identifying the model used in the demo | Adapter/config alone does not prove live execution |
| Muse Glimmer | Redacted Modal endpoint/deployment record and one successful tester session | Mock/scripted tester is not a live Glimmer run |
| SAM 3.1 | Redacted worker deployment record and output from an approved sample | Fallback cut-out is not SAM inference |
| Pipeline | One run's stage timeline and resulting ad/job identifier | Do not combine unrelated runs |
| Game quality | Actual gate report and a playable URL/file from the same run | Do not claim a pass if any required gate failed |
| Fix loop | Failed gate, proposed correction, rerun, and final result from one run | Do not stage a fix loop and describe it as spontaneous |
| Rights and media | Visible rights-confirmation flow; private consent record retained separately | Public demo should not reveal the person's contact details |
| Audio handling | Before/after technical check or application evidence showing source audio removal | Do not claim all media paths were verified unless checked |
| Face safety | SAM output/worker evidence or visible safe fallback behaviour | If SAM is unavailable, disclose the fallback |
| Evaluation | Raw `results.json`, report, manifest category counts, and real/synthetic flag | Synthetic CI results must never be presented as real-shop results |
| Gallery | Public gallery entries tied to approved evaluation ads | Empty gallery page is not evidence of 30 evaluated ads |
| Publish outputs | Each asset generated by the same demo run | Do not reuse an old output without labelling it |
| Analytics | Schema/endpoint evidence and a redacted dashboard | Do not invent visits, conversions, or sales |
| Attribution | Screenshot of end card/footer and README attribution | Keep `Built with Muse Spark Open` visible |

## Evidence folder structure suggestion

```text
private-evidence/
  run-<date>-<id>/
    provider-proof-redacted.png
    pipeline-timeline.png
    gate-report-redacted.json
    game-preview.mp4
    output-assets/              # only approved assets
  evaluation/
    manifest-redacted.json
    report.md
    results-redacted.json
```

Keep `private-evidence/` out of the project ZIP and public repository unless every file is safe and approved for publication.
