# Windows demo runbook (PowerShell)

This guide starts the local Reel2Play demo on Windows. It uses the repository's existing mock configuration by default. It does not require API keys. It does not delete or recreate any database.

## 1. Open the project folder

Open PowerShell and change to the extracted project directory. Example:

```powershell
cd E:\reel2play\reel2play
```

Confirm the expected files exist:

```powershell
Test-Path .\api\pyproject.toml
Test-Path .\engine\package.json
Test-Path .\web\package.json
Test-Path .\eval\ci.json
```

All four commands should return `True`.

## 2. Check the local tools

```powershell
python --version
uv --version
node --version
npm --version
ffmpeg -version
ffprobe -version
```

The project README specifies Python 3.12, Node 22, PostgreSQL and ffmpeg. If a command is not found, install or add that tool to PATH before continuing. Do not paste credentials into the terminal transcript or a screenshot.

## 3. Prepare local environment

Create `.env` only if it does not already exist:

```powershell
if (-not (Test-Path .\.env)) { Copy-Item .\.env.example .\.env }
```

The checked-in example defaults to `AI_MODE=mock` and local media storage. Keep those defaults for a safe synthetic rehearsal. Do not switch to `AI_MODE=live` unless the relevant providers and credentials have been configured and verified separately.

Install dependencies and build the engine:

```powershell
Set-Location .\api
uv sync
uv run playwright install chromium
Set-Location ..\engine
npm ci
npm run build
Set-Location ..\web
npm ci
Set-Location ..\workers\modal
uv sync
Set-Location ..\..
```

The Modal worker dependencies are not needed for a basic mock-mode local demo. If their installation fails and no Modal worker is being demonstrated, record that limitation and continue with the local mock path.

## 4. Check PostgreSQL without deleting anything

List PostgreSQL services:

```powershell
Get-Service *postgres*
```

If the service is stopped, open PowerShell as Administrator and start the exact service name shown by the previous command:

```powershell
Start-Service -Name "<service-name-shown-above>"
```

Check whether PostgreSQL responds:

```powershell
pg_isready -h 127.0.0.1 -p 5432
```

Check whether the project's database already exists:

```powershell
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres -c "SELECT datname FROM pg_database WHERE datname = 'reel2play';"
```

If the query returns `reel2play`, keep using it. If it returns no row, create it only after confirming that no existing project database should be used:

```powershell
createdb -h 127.0.0.1 -p 5432 -U postgres reel2play
```

**Never run `DROP DATABASE`, a fresh-verification script, or a database reset as part of this demo runbook.** Existing databases may contain work you need.

Apply migrations:

```powershell
Set-Location .\api
uv run alembic upgrade head
```

## 5. Start the API and web app

Keep two PowerShell windows open.

**PowerShell window 1 — API:**

```powershell
cd E:\reel2play\reel2play\api
uv run uvicorn reel2play.main:app --reload --port 8000
```

Open `http://127.0.0.1:8000/docs` and confirm the API docs page loads.

**PowerShell window 2 — web app:**

```powershell
cd E:\reel2play\reel2play\web
npm run dev -- --host 127.0.0.1
```

Open `http://127.0.0.1:5173`. If the page cannot reach the API, check the browser console and the API terminal; do not hide or edit away an error for the recording.

## 6. Run a synthetic rehearsal

1. Open `/try` and choose one bundled sample labelled **Synthetic sample**.
2. Keep the rights confirmation visible and confirm it before starting.
3. Run one complete sample through to the game and report.
4. Play the game and inspect the end card.
5. Open the share/output card and show only files generated by this rehearsal.
6. Keep the synthetic label visible in the recording.
7. Record the actual AI mode and any provider labels in `REHEARSAL_LOG.md`.

The default mock mode is suitable for demonstrating the product flow, but it is not evidence of live Muse Spark Open, Muse Glimmer, or SAM 3.1 execution.

## 7. Record the final demo

Follow `DEMO_SCRIPT.md` and `RECORDING_PLAN.md`. Use Windows Game Bar (`Win + Alt + R`) or another recorder already installed. Before recording, close notifications and unrelated windows. Do not show `.env`, terminal environment dumps, API headers, credentials, customer contacts, or private consent records.

After recording, watch the entire video once. Confirm that it is between 2:45 and 3:00 (unless the portal says otherwise), the UI is readable, the run is continuous or accurately labelled if edited, and every spoken claim matches the visible evidence.

## 8. Stop services

Use `Ctrl+C` in each server terminal. Do not delete the database, media directory, `.env`, or project folder as cleanup.
